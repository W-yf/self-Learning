## RV-D1-001：返回流程的时间顺序

**问题**

不考虑异常，函数按值返回且没有 NRVO 时，请按先后顺序说明：计算 `return` 表达式、初始化返回结果对象、销毁函数局部对象、函数结束、调用方使用结果、结果对象最终销毁。

**答案要点（回答后核对）**

1. 计算 `return` 表达式；
2. 初始化函数调用的结果对象；
3. 销毁 `return` 表达式相关的临时对象，然后按规则销毁函数局部对象；
4. 被调用函数结束，控制权回到调用方；
5. 调用方继续使用结果；
6. 结果对象在调用方决定的生命周期终点销毁。它不是函数退出时销毁的普通局部对象。

**常见错误**

- 认为返回结果对象会在函数结束前被销毁；
- 把“结果已经初始化”误说成“调用方已经继续执行”；
- 忽略 NRVO 时局部对象与结果对象可能是同一个对象。

## RV-D1-003：按值返回与悬空观察者

**问题**

为什么返回局部 `std::string` 的值通常安全，而返回该局部对象的引用或地址不安全？回答时指出谁拥有独立对象、谁只是观察者，以及局部对象何时结束生命周期。

**答案要点（回答后核对）**

- 按值返回会初始化一个在调用表达式中继续存活的结果对象，可能复制、移动或直接构造。
- 引用和裸指针通常只是非拥有观察者，不会延长局部对象生命周期。
- 普通局部对象在函数退出过程结束生命周期；继续通过引用或地址访问会悬空并产生未定义行为。

## RV-D1-006：Lambda 引用捕获的生命周期

**问题**

下面代码为什么不安全？只修改捕获方式并保持 `std::function<std::string()>` 的无参数调用签名，应如何修复？

```cpp
std::function<std::string()> make_reader()
{
    std::string text{"sample"};
    return [&text] { return text; };
}
```

**答案要点（回答后核对）**

- 返回的闭包对象可以继续存在，但局部 `text` 在函数退出时结束生命周期。
- `[&text]` 只保存非拥有引用关系，随后悬空。
- 改为 `[text] { return text; }`，闭包对象在 Lambda 表达式求值时保存独立副本。

## RV-R0-001：Test-first 的顺序、依据与调试价值

**问题**

面对一个已有 spec、尚无实现的新函数，说明 Test-first 的开发顺序、测试预期从哪里来，以及逐个功能尽早测试为什么能降低调试难度。

**答案要点（回答后核对）**

- 顺序是 Spec → Test → Implement；测试和函数签名本身也可能是代码，因此准确表述是“在实现代码之前”。
- 测试用例的预期行为由 spec 决定，不依赖实现采用的具体算法。
- 每完成一个小模块就验证，使未验证代码和最近改动范围较小；失败时更容易把问题定位到当前模块或近期改动。

## RV-R0-002：测试套件的 correct、thorough、small

**问题**

给定一个具体函数 spec 和若干测试，判断测试套件是否 correct、thorough、small，并分别说明依据。题面应使用新的函数和用例，不只要求背诵三个名称。

**答案要点（回答后核对）**

- correct 评价测试套件：它是 spec 的合法 client，并接受所有符合 spec 的实现；错误实现可以且应该被相应测试拒绝。
- thorough 表示能够发现实际实现中可能出现的、尤其是程序员容易犯的错误，不等于用例更多，也不保证发现所有 bug。
- small 表示用较少的用例保持快速、易维护和可频繁运行，但不能通过删除重要用例来牺牲 thorough。
